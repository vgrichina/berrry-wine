# THPS2 ExitProcess entry observer: offline implementation

The new `tools/thps2-exit-entry-observer.cjs` captures the selected invocation at the authentic runner's synchronous API-entry hook. It copies **64 raw bytes at entry ESP**, the general registers and image base, API name/main-thread identity/entry ordinal, and the **whole resident guest VFS `c:\thps2\thpcerr.log`** with an explicit 65,536-byte cap. Binary log bytes are preserved, including NULs. A missing, oversized, provider-backed, truncated or unreadable log fails capture. No emulator/game source or executable is changed.

This task executed no guest, WASM, build, acquisition, browser, box/API/SSH runtime, service or deployment operation. The tests use synthetic state, the actual runner entry prefix and the actual VirtualFS implementation. **32/32 offline tests passed**, the transformed runner passed Node syntax checking, and the staging recipe executed successfully without launching its output. These results establish an observer implementation, not original-game success or an identified failing prerequisite.

## Exact boundary and identity

The input runner is `test/run.js` at `d8cd8c54c8d63c107696f1e4ef7a1e229dcadc1e`, SHA256 `4d7b9587676db38fcf3314807acb2b2a42b5f09d2c98fcf3dccb8a6cde9e1809`, as retained in authentic capture `28d866798242da36343abdb043dad4ca2bba296d`. `transformRunner` verifies the whole source before applying five unique exact-anchor replacements. It rejects another revision or an already transformed runner. It inserts capture after API name/COM-alias resolution and `apiCount++`, before downstream formatting. It forces the API logger on, rejects native `--threads`, and rejects cooperative-worker ExitProcess rather than reading the main instance's registers for a worker call. This implementation is explicitly bounded to the authentic **main-thread** invocation.

Pinned `src/05-alu.wat` `$th_call_ind` decrements ESP and stores the actual CALL return word before `$win32_dispatch`; thunk entry and indirect JMP already own their caller's return frame. Pinned `src/09b-dispatch.wat` logs the resolved name before loading arguments and calling `$dispatch_api_table`. The observer therefore runs inside that invocation, before the ExitProcess handler can change ESP. The exact source slices and their extraction ranges/hashes are in `source-excerpts.json`; their full source identities are in `source-pins.json`.

The selected identity is ExitProcess, main thread, runner entry ordinal **3548**, ESP `0x074ffbd8`, `[ESP] = 0x004f03dc`, `[ESP+4] = 1`. It additionally reads and verifies live bytes `ff 15 b0 71 50 00` at `0x004f03d6`. A different exit or changed ordinal fails explicitly. `get_eip()` is retained verbatim: it may describe the translated block rather than the exact CALL instruction. The record labels the CALL identity as **entry return plus live code**, and does not present this inference as a separately observed instruction-PC event. No caller is selected from static candidate lists.

Every stack byte is translated separately and checked against the NULL sentinel and linear-memory bounds, so a page crossing cannot accidentally read a neighboring WASM backing. The log must expose a resident Uint8Array data property; its logical length must match `_size` when supplied. The pinned VirtualFS test performs actual create/write/append operations and verifies that unused backing capacity is excluded. No provider/accessor is invoked to materialize a file before enforcing its cap.

Returned observations contain frozen numbers/strings and copied stack/log bytes. Later guest mutations cannot change them. Reentrant observation/finalization and multiple exits latch a failure without replacing the first observation. The file adapter creates a fresh invocation directory and exclusively writes `entry-stack64.bin`, `thpcerr.log` and `entry.json`. If validation fails after the stack read, `failure.json` and the raw partial stack are retained; absent log bytes are never invented. An exit listener calls `finalize()` on retained data only and writes `verdict.json`; it does **not** poll guest state after shutdown. Acceptance requires a true verdict, matching artifact hashes and no failure receipt. Missing entry, subsequent exit, capture/write error or rejected scope produces an incomplete verdict and nonzero process exit status. A killed process without a verdict is incomplete.
