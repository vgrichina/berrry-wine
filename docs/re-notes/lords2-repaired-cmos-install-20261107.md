## First remaining blocker: PIT channel 2 calibration

`first-blocker.json` retains the consuming code, contexts, registers and terminal ring from `after-cdrom-live.json`. The original child has 3911 unique executed blocks, 180 selected records, no observer errors, block overflow, focused drops or record drops. Calls and returns balance. No GetFreeSpace consumer is observed.

The next executed consumer is original `_SETUP` segment **1:9DF6**, a CPU-speed calibration routine. Its helper **1:9E5D** writes control **B4h** to port **43h**, count **FFFFh** to **42h**, and changes port **61h** bit 0 around its instruction loops. At **1:A0AB–A0B3**, it reads port 42h twice, assembles AX and negates AX. Intel's [8254 datasheet, order 231164-005](https://www.cs.cmu.edu/~410/doc/8254.pdf), control-word table on page 6, specifies B4h as counter 2, low-byte/high-byte access, binary mode 2. Its counter and gating semantics require a running counter rather than floating-bus bytes.

The tested emulator's `$th_port_io` in `src/06b-core-handlers.wat` initializes IN results to all ones and has no port 42h branch. Channel 2 control/count writes are ignored; port 61h always reads zero and its writes are ignored. Thus the two reads in this executed path return FFh/FFh, assembling FFFFh and negating to 1. These port values follow directly from the tested source handler; the existing observer did not separately instrument port 42h. The captured helper returns independently agree: entry to **1:9E17** has AX=1; entry to **1:9E21** has AX=BX=1. Its `SUB AX,BX; STOSW` therefore stores zero. The five-sample accumulator reaches the unique final executed block **1:9E3A** with **AX=DX=0**, BX=1, SI=DI=001Ah, SS=DS=ES=0087h, CS=0047h, ESP=001F8A6Ah.

Inside that block, `MOV BX,5; DIV BX` averages zero, then `MOV BX,AX` makes BX zero. `MOV AX,FA00h; MOV CX,04A9h; XOR DX,DX; MUL CX` produces DX:AX=048D:0A00. The next instruction, **1:9E4B `DIV BX`**, therefore has a zero divisor. The existing `$th_div16` raises C0000094 for this condition. The console directly records child retirement `Thread 1 exited (postYield=2) prev_eip=0x179e3a esp=0x1f8a6a`, and captures show the resulting empty desktop.

The exact 9E4B instruction and exception code are **derived from the captured final block's entry registers and straight-line code**, not a separately captured fault-time EIP/exception record. The precise source defect is absent PIT channel 2 state/read/count/gate behavior; the DIV zero check should remain strict.
