# GL raster-position family, 2026-11-02

The remaining 23 GL1.1 RasterPos aliases resolve to numeric adapters and a native homogeneous raster operation. Existing scalar2f retains its entry point. No alias emits a primitive or defers failure to a stub.

## Primary specification

[OpenGL1.1 specification, March4 1997](https://registry.khronos.org/OpenGL/specs/gl/glspec11.pdf), sections2.10,2.12,2.13,3.7 and table6.5 define this contract. Two coordinates supply z=0,w=1; three supply w=1. RasterPos applies modelview and projection, clips as a point, maps into the viewport/depth range, and retains clip w. Valid calls compute associated color and texture coordinates like a vertex, including lighting, texgen and the texture matrix; bitmap fragments reuse those values. Invalid calls clear validity; their other associated values are indeterminate. The associated eye distance may be approximated, and this implementation uses Euclidean distance after eye-space dehomogenization. Raster attributes belong to CURRENT_BIT. Lists capture supplied coordinates while transformations and associated state are evaluated at execution. A RasterPos inside Begin/End generates INVALID_OPERATION.

## Implementation

All typed entry points validate their complete guest stack/vector span before mutating GL state. Binary64 slots occupy eight bytes, scalar short slots four bytes, and vector shorts two. Signed integer values convert numerically, without normalization. Sparse guest pages are translated independently. Native canonical opcode146 owns four homogeneous f32 coordinates and list value capture; opcode130 preserves the existing2f path.

The per-context raster state includes validity, window xyz, clipw, color, distance and both units' full homogeneous texture coordinates. Named modelview/projection stacks are independent of the selected matrix mode. The default viewport temporary no longer overlaps the client attribute stack head. The existing native lighting evaluator receives a private record and authoritative native capabilities; it uses front material and current normal with reverse-normal disabled, then clamps RGBA. A private normal is solved through the full4D inverse transpose before evaluation, including non-affine modelview matrices; primitive callers retain their existing helper contract. This shares the renderer's existing light model rather than claiming extra light-model features.

Raster texgen supports independent S/T/R/Q enables, object and eye-linear planes, sphere S/T, per-unit/context state, and TEXTURE_BIT/ENABLE_BIT restoration. Eye planes use a pivoted f64 solve against modelview transpose at specification time, including non-affine matrices. Texture matrices run once at RasterPos. Bitmap records use the existing software worker snapshot queue and retain captured raster attributes while snapshotting draw-time fragment state. Worker replay selects the bitmap raster loop directly. Bitmap drawing now carries captured coordinates/color/distance to software fragment tests and a WebGL bitmap vertex program sharing ordinary texture/fog/alpha fragment processing; later matrices, normals, materials and current coordinates cannot recompute them.
