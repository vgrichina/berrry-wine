## Original rules and lifecycle

The local original Help describes the double-headed wallbuilder arrow:
up/down means vertical, left/right horizontal. Left click starts growth;
right click changes orientation. Walls grow both ways and must anchor before
an atom strikes. A single anchored half may remain after a collision, which
costs a life; that partial wall is not a completed partition. With two atoms
the second collision ends the game. Time expiry also ends it. Clearing at
least 75% advances a level; bonus points are distinct from proof of completion.
Scores count cleared squares and isolated empty regions.

The Help's strategy suggests centered vertical walls and dividing atom groups.
This is rules information, not a trajectory predictor or a preselected move.
Each actual wall choice must come from the current complete scene.
`original-help-prose.log` retains static phrase-expanded original prose with
formatting omitted. The existing generic fulltext helper misaddresses this
old phrase table; the inspection instead interprets offsets relative to the
offset table and two-byte references as ((first-1)*256+second)/2. No parser or
runtime source was changed for that inspection.

The released Win16 lifecycle regressions were read before play. They cover
owner disabling before WM_INITDIALOG, modal mouse activation/eating, nested
dialogs, pre-disabled/absent/destroyed owners, cancellation, EndDialog during
init, stack restoration and invalid/stale destruction. The modal destruction
fixture also checks guest-owned handle retirement and reuse. The renderer
regression preserves queued native-control UP into the modal pump.
The existing WEP4 gameplay test proves live red/blue wall growth, not completed
walls. It is not run as a substitute original and its old coordinates are not
used for this task.

## Guarded personal control

`tools/jezzball-controller.py` derives the released finite-click controller
and Barrage identity transport. One bootstrap or active-board review binds
the exact PID/start token/window once. Actual active level-one board admission
requires personally reviewed rules, orientation, partition and counters.
Wall choices require a raw complete scene at most five seconds old; menus
allow thirty seconds. Each placement attests its visible orientation, reason,
no existing growth, no modal and review of the preceding result. Completion
reviews require a persistent partition; animation alone cannot qualify.
Area alone cannot qualify as a natural outcome.

The CLI's canvas PNG omits the OS cursor. The owned capture route therefore
also reads exactly `renderer.canvas.style?.cursor || 'default'`, the public
display output, without reading a guest handle, game variable or memory.
It preserves the raw complete canvas unchanged, retaining the current cursor
CSS and converting its existing CUR bytes to a separately named PNG with local
ImageMagick. This is visual format conversion, with no orientation recognition.
An absent cursor remains unknown. Cursor-based personal reviews check the
native identity, complete-scene hash, cursor PNG hash and original freshness;
the model must inspect both visual surfaces. No cursor image is manufactured.
The headless canvas lacks a style object, so a small run-specific preload
generated by the published controller wraps its canvas factory and retains
`canvas.style ||= {}`. Existing native SetCursor output can then reach that
public display property. This adds no guest calls, input hooks or game settings.
A separately tested, single guarded pointer-only hover can expose that cursor
before the first wall. Hover requires a fresh five-second complete scene and
must produce no mouse-down. It is not a wall or an orientation-changing event.

Every wall and menu event is one finite left click, at most 1,500 ms, with independent UP
prearmed at a 1,750 ms fallback. The controller waits for physical release
before subsequent capture or audit. UNKNOWN, cancellation, mixed identity,
parent/child failure and late ACK end the chain with no retry or rebinding.
The 180-second Quit reserve is irreversible. Native Quit and host teardown
remain separate evidence. A final native exit before UP can be recorded only
with its actual normal wait and both EOFs; physical UP remains unacknowledged.

The production endpoint has no tested right-button guarded semantics.
Right clicks, extra button arguments and raw bypasses are refused. No orientation
event is enabled. No recognition, ball tracking, private game state, solver,
action list, guest clock, configuration or seed change is used.
Completion stays modal; the controller has no Next Level route or completion
dismissal route. No owner click-through or second level is authorized.
