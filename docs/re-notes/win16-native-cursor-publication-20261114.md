# Native Win16 cursor loading and public publication

The generic cursor path now resolves supported predefined system IDs and module-qualified NE GROUP_CURSOR/CURSOR resources, including ordinal IDs and names passed as far strings. USER.69 calls the shared SetCursor implementation and returns the previous narrowed handle. GetCursor and ShowCursor use the same per-thread public state as the host renderer. NULL removes the cursor; invalid handles/modules and missing or malformed resources fail without changing the selection.

NE group entries select an actual child image, whose LOCALHEADER supplies the hotspot. The existing bounded classic DIB decoder copies the AND/XOR planes into owned bitmap records. Loaded cursors retain module ownership, survive DestroyCursor/DestroyIcon, and retire when their module unloads. Unload clears threads selecting those retired records. A shared NE cursor resends its pixels to each selecting host instance because the host CSS cache is private to that instance. Private cursor caching and destruction remain covered by the adjacent cursor/icon suite. Unsupported image encodings fail instead of returning a fabricated cursor.

The real native baseline completed its far-Pascal calls but returned handle 257 for both system IDs and published no cursor event. Its assertion failed on actual distinct-handle semantics. The repaired native fixture executes imported USER/KERNEL calls through the production WASM, not test-only WAT API wrappers. It proves:

- System 0x7f84 and 0x7f85 produce distinct handles and actual host `ew-resize` and `ns-resize` output; previous-handle and NULL results agree with those selections.
- Two different NE cursor images, raw CURSOR lookup, repeated shared loads, named far-string lookup, and identical IDs in two loaded modules preserve identity and actual distinct host pixels.
- AND-mask transparency, visible pixels and the two resource hotspots reach the shipping host CUR encoder. The selected PNGs are decoded from that actual encoder output and were personally viewed. They are synthetic fixture cursors, not game captures.
- Invalid module/ID/handle, malformed resource and NULL/invalid destruction fail; shared destruction preserves the resource; unloading one module leaves the other cursor usable, and unloading the selected module clears the public selection.
- A real registered native window gains and loses focus without changing its installed cursor. Two WASM instances over one memory execute native far calls on different input threads, preserve the first thread's selection, and publish pixels into the second host's initially empty cache. Both Pascal stacks restore.
