The original loading chain is:

| Original source/address | Behavior and implication |
| --- | --- |
| `level0.lua:342`; `level1.lua:95–103` | New Game chooses level1/checkpoint9, mapped to sectionD/Intro Movie A. |
| `mdk2.lua:373–398` | Applies/pends `game`, destroys `Level`/`Save`, collects garbage, sets checkpoint/level/section, then loads the new level script. Nil `Level` is legitimate construction. |
| `level1.lua:1–4`; `mdk2.lua:477` | Creates `Level`, names `l1`/`loadscreen1`, sets scenegraph processing, and calls loading before object/scenegraph application. Those fields do not prove artwork or a playable scene. |

| `0x438be0 -> 0x42b320` | Original Lua loading-screen wrapper/function. The loop checks queue count at `0x5ce0c0`; positive count continues. After count drains, its fade must also finish. The ordinary two-argument call does not use the optional message gate. |
| `0x42b446 -> 0x44f930` | Loading-screen loop pumps a resource. If `0x4b7d14` is already nonzero, it keeps working on that entry. It dequeues a new one only when there is no active entry. Queue count can remain unchanged across many pumps. |
| `0x452140` | Prepares storage/archive input and the output buffer; publishes request pointer `0x4b87d4`, completion `0x4b87d0=0`, request flag `0x4b87cc=1`. |
| `0x451f30` | Original file-worker loop clears the request flag, calls `0x4520b0` on that pointer, then sets completion to 1 at `0x451f51`. Its idle loop calls alertable SleepEx with zero milliseconds. |
| `0x4520b0` | Reads the direct-file branch or calls the archive branch (`0x457600`), releases input storage, and adds the resource size to `0x5ce08c`. A request flag already cleared with completion still zero can mean work is in flight. |
| `0x4522d0 -> 0x4515c0` | Polls completion after `SleepEx(10, TRUE)`. An unchanged active pointer does not distinguish sleep, file work, decode or finalization. |
| `0x44fa32–0x44fa6f` | Completion 1 marks entry status 2, finalizes it and clears active/retries. Return -1 increments retries; at five retries the pump stops progressing that entry and the loading-screen function has resource-error UI. None of those retry values was measured live. |
| `0x44f8e0` | Separate `chIsLoadingResources` query returns true for a nonzero active pointer or positive queue. This query alone does not identify comic/tutorial readiness. |

Selected disassembly is in `RUN/native-*.txt`. Calls `0x44fd30` and `0x451430`, which appear around the pump, are respectively an immediate return and a zero return in this exact original binary; they are not evidence of an unserviced host callback. The older GL-initialization suspended-file-worker failure documented in [mdk2-demo.md](mdk2-demo.md) happened before window creation. The current retained run reached the original title and native New Game/Medium callbacks. That older failure cannot be assigned to this boundary without new worker-state evidence.

The actual host path matters: retained state reports `guestWorker:true`, worker thread backend, one frozen host, and a sibling file-worker incarnation. `host.js:_runThreaded` runs the main slice and sibling thread scheduling in the same rendezvous; a main Sleep deadline parks the main execution while siblings continue receiving turns. `handle_SleepEx` in `src/09a0-handlers-base.wat` uses the normal sleep yield and submitting-thread alertable APC machinery. `_frozenPump` consumes one credit and advances the guest clock per slice. With no credits it parks. Human inspection time therefore does not run the game or advance its guest clock. Source scheduling permits progress; it does not prove that this particular worker executed or completed its request.
