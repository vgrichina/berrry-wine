[Wine's Win16 export specification](https://raw.githubusercontent.com/wine-mirror/wine/master/dlls/user.exe16/user.exe16.spec) identifies the Pascal WORD/far-pointer/WORD/WORD signature and BOOL16 return. Its [Win16 window adapter](https://raw.githubusercontent.com/wine-mirror/wine/master/dlls/user.exe16/window.c) widens signed RECT16 coordinates and translates window and GDI handles while preserving the flag values. Ten argument bytes and the four-byte far return are callee-owned. From SP+4 the words are flags, HRGN, rectangle offset, rectangle selector, HWND. A nonzero selector with offset zero is a valid pointer.

The [RedrawWindow documentation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-redrawwindow) makes `0x0101` an invalidation followed by synchronous processing of required paint. Ordinary invalidation remains deferred. Erasure requested with INVALIDATE belongs to painting; a sender must not erase before BeginPaint. A clean UPDATENOW must not invent damage. A nested callback may create new damage that must survive the outer EndPaint.

The existing Win32 handler mutates a bounding update rectangle but does not read HRGN or complete synchronous painting. The existing Win16 UpdateWindow continuation already retains each invocation's return record on the guest stack and runs far WM_PAINT, including nested BeginPaint's WM_ERASEBKGND and its DX:AX result. Reusing that callback path avoids sending a 32-bit callback frame to 16-bit code. The shared damage model itself remains a bounding rectangle.
