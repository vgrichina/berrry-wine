# Lords2 PIT calibration

Task: NEW-GAME-LORDS2-DEMO-20261015. Evidence: `scratch/runs/20261107-lords2-pit-calibration/`. Follows [the repaired CMOS installation attempt](lords2-repaired-cmos-install-20261107.md).

The prior original is evidence, not another run authorization. Its retained blocks show eleven helper calls: one warmup followed by five pairs of timing samples. Each helper lowers channel 2's gate through port 61h, writes B4h to port 43h and FFFFh low/high to port 42h, raises the gate, executes a divide loop, restores the gate-low control, and reads the counter low/high. The sample pair compares 16-bit and operand-size-prefixed 32-bit division loops. The captured returns are both AX=1; five subtractions accumulate zero. Final block 1:9E3A averages that zero and subsequently divides a nonzero product by the zero average. The prior run did not separately capture the fault-time instruction or exception code. `prior-calibration-blocks.json` retains the selected evidence and identifies its exact source hash.

Intel's [8254 datasheet, order 231164-005](https://www.cs.cmu.edu/~410/doc/8254.pdf), describes B4h as channel 2, low/high access, binary mode 2. A low gate stops decrementing; its next rising edge reloads on a clock pulse. A count latch persists until consumed and ignores repeated latch commands; status read-back takes priority over count bytes. Count-register writes and counting-element transfers are distinct. [Intel's PIIX4 datasheet, order 290562-001](https://0x04.net/~mwk/doc/intel/82371ab.pdf), sections 4.2.3, 4.2.4.1 and 8.8, documents the port mapping, channel-2 gate on 61h bit 0 and output status on bit 5.

Before the repair, both retained module variants reproduced the complete causal chain using generated ordinary Win16 instructions: ten samples equal 1, average zero, exception C0000094 at the generated DIV instruction, then unhandled CPU termination and yield 2. This confirms the timer mismatch without changing exception handling. The new production regression rejects those old modules because they lack the PIT import.

The repair routes immediate and DX IN/OUT instructions for ports 40h–43h and 61h through a process-owned polled binary mode-2 8254. It implements low/high and single-byte access, independent read/write phases, count/status latches and read-back priority, deferred count transfer, periodic reload, gate freeze/restart, channel-2 OUT status, and zero-as-65536. Counter 0 starts in the firmware rate-generator configuration used by the existing seed consumer. Clock input is elapsed monotonic time at 1,193,182 Hz, independent of guest batch time and calendar changes; reads do not advance it. Cooperative contexts share the device and OS Workers serialize returning imports through existing synchronous RPC. Unsupported modes, BCD, illegal mode-2 count 1 and wide accesses fail explicitly. IRQ/audio generation is outside this polled device.

The locked full build passed, as did generated instruction calibration and sequencing controls on standard and compatibility modules, host-state/isolation and real OS-Worker controls, CMOS/calendar/worker integration, existing x86 operation and upper-half regressions, and the channel-0 seed consumer. Armed/disabled/saturated observer controls preserve architecture and the complete 512 MiB memory on both modules, including the strict floating-port fault control. The first fixture-control failure was a test scratch-store collision with its inherited fixture's saved SP; relocating the new scratch bytes fixed the fixture without production changes.

A separate natural-clock generated consumer measured unequal samples, but still raised C0000094 at the final 16-bit division: its measured average (294 standard, 292 compatibility in this observation) produces a quotient above FFFFh for the generated numerator. This is retained as a calibration-range limitation, not a success or reason to alter clock rate or substitute a guest result. The ordinary original attempt will establish the actual guest's outcome.
