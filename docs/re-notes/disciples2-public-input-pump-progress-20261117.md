## Published observation route

`WINE_PUBLIC_INPUT_TRACE=/absolute/new-file.jsonl` and an authored native fixture.
`lib/cli-public-input-trace.js` observes existing host queue/ticket objects,
renderer poll entry/return, native pump idle notifications, cancellation and
independent release. It assigns object identities to queued events and records
monotonic and wall timestamps. It reads no guest memory, invokes no additional
guest API and changes no input scheduling, validation, deadline or receipt rule.
Disabled tracing installs no poll wrappers.

The trace caps tickets at 64 and rows per ticket at 512, retaining a prefix and
latest tail with overwrite counts. Queue snapshots include at most eight event
headers. Observation ends at the immutable ticket deadline plus 1750 ms; file
writes occur at lifecycle boundaries and exit. Hover generations are serialized
as strings because native `wnd_lookup_generation` returns BigInt. The initial
serialization failure and its failed qualification remain in the run directory.

## Actual original boundary

Media preflight checked all 128 existing files before native launch. The pipeline
used shipped defaults, real ticks, no `f.sg` or imported save, a prearmed independent
3620-second watchdog, fixed 3600-second native lifetime and 300-second Quit reserve.
Every intent followed personal review of a complete fresh image with a new nonce.
The five setup confirmations were 57.0, 98.1, 61.2, 83.0 and 202.1 ms; their
independent physical releases completed in 142–161 ms.

Continue at displayed (963,620) mapped to native (780,522), HWND `0x10001`.
The reviewed public window record identifies its thread as 1; the invisible
`CMqThread` HWND `0x19001` belongs to thread 4. Relative to ticket preparation:

| Time, ms | Public observation |
| ---: | --- |
| 11.912 | Host handler entered. |
| 16.950 | Handler returned with MOVE 21, hit-test 22, DOWN 23 queued. |
| 33.337 | Renderer returned MOVE 21; hover became native-pump/pending, not polled. |
| 46.267 | Renderer returned hit-test 22; DOWN 23 remained queued. |
| 48.881–490.061 | 38 subsequent renderer polls returned empty with DOWN 23 still queued and hover `polled:false`. |
| 505.216 | Cancellation purge began with that exact DOWN 23 still pending. |
| 505.241 | Purge completed with no queued DOWN. |
| 510.073 | Transport disconnect recorded sticky UNKNOWN; cleanup UP 24 was queued. |
| 528.473 | Renderer returned distinct UP 24. |
| 1311.489 | Independently armed physical release completed. |

There were 40 renderer poll returns before purge and 35 native idle notifications,
all for thread 4. None acknowledged target thread 1. The retained ticket has 239
rows, no overwrites, and no DOWN-return candidate. The queue was actively polled;
this is not evidence of an unpolled FIFO or a handler falsely counted as consumed.
Purge follows the unresolved barrier and disconnect; it is not established as the
original scheduling defect. Host poll rows do not identify the calling native
thread or native Peek/GetMessage arguments/results. Continuous native messages,
filtered target polls, thread routing and other reasons for the missing target
acknowledgment remain distinguishable hypotheses, not findings.

Changing the barrier to accept a sibling's idle notification would discard the
existing thread/window ownership condition. No such repair, synthetic CONSUMED,
late DOWN, timeout widening or validation bypass was made. A follow-up can use
retained logs and authored native fixtures to distinguish the target thread's
public Peek/GetMessage filtering and exhaustion behavior. This worker has used
its sole diagnostic original and cannot run another under this authorization.
