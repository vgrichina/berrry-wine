## Position, heading and contact

`100e77a0` initializes the temporary movement structure with the Player's `+14` client-state pointer at its `+0`. `100e9b85` prepares it, `100e9b8f` runs movement, and `100e9b9e` copies results through `100e7580` (a second path does the same). Thus the fields below belong to that selected Player's state, rather than the export table or a guessed global.

* **Origin:** `100e7633: d9 40 18`, followed by loads at `+1c/+20`, supplies the origin setter through Player virtual slot `+28` (`100899e0`). The unbound path `10089b50` onward writes object `+90/+94/+98`; the later setter copies it into its record. The decoder compares state `+18..20` and object `+90..98` and rejects bound entities (`object+140 != 0`) and mismatches. It does not silently choose between transformed origins.
* **View heading:** `100e75b9: 8b 88 a4 00 00 00` then `100e75bf: 89 8e a0 04 00 00` copies state `+a4` into object `+4a0`. Adjacent copies establish pitch/yaw/roll at state `+a0/+a4/+a8`, object `+49c/+4a0/+4a4`. `100e8a72` loads object `+4a0`; `100e8a78` multiplies by original double `[101822b8] = 0.017453292519943295`; `100e8a86`/`100e8a8e` execute `fsin`/`fcos`. The following products give forward `(cos(pitch)cos(yaw), cos(pitch)sin(yaw), -sin(pitch))`. This establishes degrees, yaw zero toward +X and positive yaw toward +Y. This is native view yaw, not a measured movement bearing, body yaw, or proven final camera orientation. The decoder requires matching Player/state view copies.
* **Contact entity:** `100e772f: 8b 41 44` reads state `+44`; `100e7732: 3d ff 03 00 00` tests absent-contact sentinel `3ff`. Original LEAs at `100e7740..100e775c` and `100e776a..100e777b` compute `records + index*2dc`. `100e775f` writes object `+e4` only when the contents-depth level is below 2; `100e777e` writes `+e8` regardless of that level. Both are cleared first at `100e7721/27`. The decoder checks these relationships and validates any target record's bounds, active flag and index.
* **Support flags:** state `+48` and `+4c` are copied from movement globals `[10416878]` and `[1041687c]` at `10060a7c: 89 42 48` and `10060a8e: 89 42 4c`. The former selects movement branch `10060060` at `10061160..68`; the latter records existence of a collision plane. The decoder exposes both separately as `walking` and `groundPlane`.

The actual contact producer is `10060740`, called before and after motion at `10061130` and `10061189`. It traces from state origin to origin minus **0.25 Z** (`10060763: fsub qword [10183028]`, original double 0.25), using the native bounds and callback `pmove+d4`. It copies the 60-byte trace into state `+60` at `100607b2..c0`.

No-hit fraction 1.0 takes `10060849..54`, writing state `+44 = 3ff` and clearing plane; `10060944..52` clears walking. The steep-plane path can instead write `3ff`, **plane 1, walking 0** (`10060933..52`). Plane-normal thresholds come from original stores of approximately 0.98 or 0.7 at `100607cf/db`, depending on surface bit `02000000`; the steep path has additional velocity handling, so a simple threshold comparison is insufficient.
