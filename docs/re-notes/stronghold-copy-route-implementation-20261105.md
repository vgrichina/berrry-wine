## Actual selected copy and ordinary publication

`host.js` forwards the existing dirty/retained-lock policy as observation data;
its decisions remain unchanged. `lib/host-imports.js` emits a receipt only after
the selected memory-to-destination copy. It records allocation generation,
source slot/storage extent/geometry/flags, selection, owning memory/window,
destination layer/canvas, clipping, copy generation, lock policy and frozen
step. Startup census generation zero remains unknown. Slot reuse, even at the
same address and size, invalidates the old receipt.

`lib/renderer.js` exposes passive hooks after actual transfers and successful
ordinary publication. The observer follows the selected destination through
windowed blits, exclusive intermediates and final filter publication. It also
checks output/filter generation and guards destination writes and canvas size
setters, including a same-size reset. Publication failure cannot reuse the
previous receipt. No extra present, flush, readback, guest write, time change,
scheduler action, lock-policy change or hold release is requested.

The transaction pins the live host, process, instance, memory, renderer/context,
window/layer/canvas, broker, guest/link/Worker/Module, endpoint and Worker URL.
Foreign or replaced lifetimes reject. Normal calls preserve their original
receiver, return/Promise, exception and order; cleanup restores owned hooks.
Unknown output paths stay unknown. Tests cover software Canvas2D output and
the real software presentation filter; GPU/browser output is not qualified.

This establishes the actual copy-to-publication dataflow. It does not identify
an original graphics operation that caused every source byte, prove complete
pixel coverage/occlusion, or certify that a retained pointer finished its write.
The older operation-to-upload relation remains unknown.

## Capture and route consumer

`createAttachment.capture` returns the joined native/host capture transaction.
The generated `freshShot` returns it as `nativeObservation`; the generated route
adapter passes it to `diagnosticScene`. The consumer recomputes the join and
checks the actual PNG digest plus capture name, step, command and epoch. The
previous setup screenshot whitelist and exported hash list are removed.

The join requires complete bounded running reports, contiguous record identity,
the executed gate/reset/pass/draw history and checked returns, current selected
primary allocation/copy, the actual compositor lineage/publication, a complete
64-step ACK and its matching capture bracket. Native boundary count and native
receipt must remain unchanged from ACK to capture. This detects execution
during a screenshot even when PC and ESP end at the same values.

Missing, malformed, foreign, stale, replaced, partial, terminal, pending-async,
or exhausted provenance returns unknown or a latched terminal rejection. The
consumer distinguishes a proved in-progress setup diagnostic from completed
cycle status, pixel acceptance, input readiness and gameplay. It grants none
of the latter conditions.
