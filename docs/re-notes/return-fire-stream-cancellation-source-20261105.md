## Source-supported mechanism and causal limit

The [151.0.7922.108 body-loader source](https://chromium.googlesource.com/chromium/src/+/refs/tags/151.0.7922.108/third_party/blink/renderer/platform/loader/fetch/response_body_loader.cc)
notifies its downstream client in OnStateChange before recording the terminal
public state. Cancel tests its internal loading state and can select
CancelSync/DidCancelLoadingBody. In the
[body-stream source](https://chromium.googlesource.com/chromium/src/+/refs/tags/151.0.7922.108/third_party/blink/renderer/core/fetch/body_stream_buffer.cc),
normal closed-state handling calls Close and then CancelConsumer. The
[resource loader](https://chromium.googlesource.com/chromium/src/+/refs/tags/151.0.7922.108/third_party/blink/renderer/platform/loader/fetch/resource_loader.cc)
turns DidCancelLoadingBody into Cancel/CancelledError. This explains how a
normally closed consumer stream can coexist with a failed Network terminal,
without any explicit JavaScript abort or teardown. Native traces and the
tail-timing comparison support this explanation but do not expose the internal
state values or the complete C++ stack.

Live Browser.getVersion reports Chrome/151.0.7922.108, V8 15.1.206.16 and a
zero source revision. Installed dpkg metadata says 151.0.7922.71-1. Actual
`/opt/google/chrome/chrome` SHA-256 is
`22e4d5ef0c637a87b59a9baad42625aba3284dc03d4a5908748e253556318c97`.
The source tag is therefore a candidate implementation, not verified binary
provenance. Primary URL/file hashes and relevant excerpts are retained. A
Gitiles history request returned HTTP 403 at 16:20:08Z; that history operation
stopped without retry or alternate-history access. No upstream-fix claim is made.

The [Fetch garbage-collection rules](https://fetch.spec.whatwg.org/#garbage-collection)
alone do not identify this cancellation. It occurs with strongly retained
response/reader/controller, normal closed/done observations and no signal
abort, well before explicit lifetime cleanup. The direct demonstrated boundary
is browser body-loader cancellation; the exact bookkeeping/reentrancy sequence
remains an inference. Next discriminating evidence would be a source-mapped
native stack/state capture at DelegatingBytesConsumer::Cancel/CancelSync,
BodyStreamBuffer::Close and HandleResult on this same generated fixture,
showing terminal notification order. No browser/version sweep or speculative
project change is warranted.

The original immutable failure remains SHA-256
`bfc438fad8a6173442ba8867f276bc948a4812de2f7b5093bebd24ab15ee5f78`.
Neither full original delivery nor this native path in that original is proved.
