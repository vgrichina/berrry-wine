## Durable ownership repair

`tools/blood2-durable-launcher.cjs` introduces an app-specific detached receipt
owner. The submitter completes immutable preparation, then transfers the
same read-only descriptors through exec. The detached owner has ignored
stdin and regular-file output; it retains the existing Linux
`native-supervise.cjs` containment (actual available level: pdeathsig).
The supervised run prearms a separate finite watchdog before native launch.
Native and watchdog pipes are streamed to files as observed and fsynced
at close, rather than held solely in the submitter's memory. Their direct
parent records actual close waits and both EOFs. The outer owner reports
missing waits as missing, rather than assuming successful receipt retention.
Worker cancellation remains host cleanup, never ordinary guest Quit.

Both final controls deliberately kill the submitting process before native
interaction: TERM in one and SIGKILL in the other. Each detached run remains
controllable, completes Enter/loading, and retains native exit 0, watchdog
exit 0, actual waits, separate stdout/stderr EOFs, empty drain errors and
`leaked:false` containment. The native processes receive worker-owned
orderly cancellation after the test scope closes. This demonstrates current
submitter-death survival; it does not identify the historical signal sender
or establish the historical native exit.
