2. NVIDIA, Doug Rogers, Color Key in Direct3D, pages 2-5 (PDF indices 1-4):
https://developer.download.nvidia.com/assets/gamedev/docs/ColorKey.pdf
Describes a DDK-derived pipeline that retains keyed RGB, sets keyed alpha to
zero before filtering, and uses alpha testing. In its example a single keyed
tap at equal weights gives alpha 0.75. It describes implicit GREATER0 testing
when application testing is disabled, and explicitly discusses TNT behavior.
It references DX6/DX5, never state144. Its texture-alpha precedence discussion
does not establish DDPCAPS_ALPHA palette semantics. This is concrete vendor
evidence against treating any-match rejection as an obvious universal legacy
rule, but cannot alone specify the later DX7 FALSE contract.

3. Intel G45 PRM, volume 4, section 4.3.1.2, printed page 110; SAMPLER_STATE,
printed page 147:
https://cdrdv2-public.intel.com/691014/g45_vol_4_subsystem.pdf
Lists hardware modes for any-contributing-match rejection and zero-RGBA
replacement. Only replacement is explicitly associated with Direct3D's
COLORKEYBLENDENABLE functionality. The other mode's existence and numeric
value zero do not establish the API FALSE mapping, API default, or treatment
of zero-weight taps. Do not infer the missing API contract from this table.

4. Microsoft's current D3DPRIMCAPS driver reference:
https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dcaps/ns-d3dcaps-_d3dprimcaps

Current source and the missing oracle

lib/d3dim-gpu.js:810 enables fixed-function colorKey only for effective keys
with keyBlend false; lib/d3d9-fixed.js:347 discards sample0.a below 0.5.
The upload mode preserves keyed RGB while clearing alpha. Thus mixed-key
coverage currently receives a fixed half-alpha cutoff, not any-match reject

Bounded reference experiment required before implementation

Use an authenticated native DX7 runtime, record OS/runtime DLL hashes, device
GUID, driver/version, returned caps, each HRESULT, states and surface formats.
First GetRenderState(144) on a fresh device; then explicitly set FALSE. Never
substitute the emulator's zero-initialized storage for native default evidence.
Probe HAL and available Microsoft reference/software device separately; do
not combine differing results into one invented normative result.

Use an ordinary P8 2x2 texture: key index7 magenta, nonkey8 green, nonkey9
magenta (same RGB as key). Set real DDCKEY_SRCBLT=7. No alpha palette, mipmaps,
fog, lighting, dithering, or blending. Select texture color and alpha at stage0,
disable stage1. Use constant TL UVs over an interior covered pixel and a blue
clear. For normalized coordinates x=u*2-0.5, y=v*2-0.5, choose binary-exact
texel centers (.25,.25) and midpoint (.5,.5), avoiding triangle edges.

Initial classification: exactly five linear midpoint draws with 0,1,2,3,4
keyed taps and remaining green taps; application alpha testing disabled.
The following are hypotheses to discriminate, NOT expected conformance values:

  keyed tap count       0    1    2    3    4
  any-match reject      draw keep keep keep keep
  alpha <0.5 reject     draw draw draw keep keep
  alpha <=0 reject     draw draw draw draw keep

Here keep means unchanged blue destination. Record all RGBA; retaining RGB
and zeroing RGB yield different surviving colors. Two keyed taps also probe
the half-alpha boundary: record raw precision instead of accepting tolerance
that conflates reject/pass. Compare software RGB separately from XRGB's
nonsemantic X byte; direct GPU RGBA and Worker DIB alpha are different ABIs.

Then six membership/weight controls: point index7, point duplicate index9,
linear all7, linear all9, center of index8 with only zero-weight neighbors
keyed, and the same footprint with a positive key weight 1/256 (u=.251953125,
v=.25 with a keyed right neighbor). Add unkeyed state41 FALSE control.

On the one-key and three-key midpoint cases, run application tests ALWAYS,
GREATER0 and EQUAL255, then select opaque diffuse alpha with GREATER0. These
eight draws distinguish independent rejection from application-alpha control.
For each of the initial five cases, repeat near z=.25 then draw far untextured
green z=.75 with LESS and writes enabled; color reveals rejected depth writes.
Core bounded matrix: 25 draw configurations plus five far occlusion draws;
this includes the state41 control. Record the fresh-state query separately.

Only after source or native evidence resolves each row, encode those rows in
the existing CPU sampler/draw, WebGL1/2 pixel and actual Worker fixtures. Add
wrap/mirror/clamp seams, RGB565 fast16 versus general path, and a keyed/nonkey
duplicate-color footprint. Border addressing and DDPCAPS_ALPHA precedence
require their own evidence; do not silently widen this result to them.
Require an isolated mutation of the chosen cutoff/membership rule to fail the
new oracle, with an unchanged-input cache-hit prerequisite for Worker reuse.
