Source causal chain
lib/dll-loader.js dllMainSteps yields its generator only for reasons 3/5
(nested COM/LoadLibrary). Halt 4 exits the loop, constructs incomplete outcome,
and restores caller EIP/ESP/registers/SEH/yield. finishDllMain then throws under
requireCompletion. callDllMain's finally releases its callback gate depth.
notifyDllThreadOwned unwinds the module snapshot and _notifyThreadAttach
releases the outer gate. runSlice invokes attach before wait polling, outside
its normal e.run exception handling. This explains restored crash-report EIP.
Increasing maxBlocks cannot release another cooperative thread's section.

Proposed explicit interface (not yet implemented)
Add a cooperative notification operation, separate from synchronous/Worker
wrappers: beginDllThreadNotification(opts, reason, fallback) returns null if
gate busy, otherwise an operation tied to exports/current thread identity.
Operation owns one outer gate, one pinned ordered generation snapshot, a
module cursor, and one active callback generator. advance(quantum) returns
{status: 'parked'|'quantum'|'completed'|'exited'|'fault', ...diagnostics}.
Parked includes actual yield reason/halt/EIP/ESP and requests normal scheduler
wait service. No caller restore, token publication, pin release, cursor advance,
or gate release occurs for parked/quantum. Never clear a wait inside advance.
Resume must reject another instance/owner and re-entry while advancing.

dllMainSteps needs an explicit cooperative mode: yield typed scheduling events
after one run quantum, rather than internally consuming 64 runs or finishing on
halt 4. Preserve the current sync and async default semantics and numeric
maxBlocks API; existing drivers must never mistake a new schedule event for a
LoadLibrary request. Nested asynchronous host lookup retains its generator and
gate and must not run that instance while awaiting its result. Generator.return
currently skips the restore tail: cancellation needs an explicit finalizer, not
an assumed finally. Completion still requires EIP=0 AND restored stdcall ESP,
no fault and no terminal yield; EAX false is valid THREAD_ATTACH completion.

ThreadManager integration boundary
Store operation on thread, not on manager. First scheduling turn may begin it
only after gate acquisition; subsequent turns poll the operation's existing
wait before advancing it. Existing runSlice reason-9 behavior clears the yield
and gives up the turn; preserve that ordering so section holders run. Extract
shared wait preparation and post-run accounting so callback quanta get the same
sleep deadlines, synchronization results, step/wall budget and progress metrics
as ordinary code. Only the operation advances callback guest execution; the
normal e.run path must never run the saved thread procedure until all modules
complete. Keep _runningThreadHandle scoped to actual execution, while the gate
remains owned by the guest thread across host turns. Already attached peers may
run ordinary code; another thread's attach/detach/load callback must remain
parked behind the gate. Do not recursively call runSlice to pump a holder.

Advance cursor exactly once after successful callback return. Keep snapshot
pins throughout suspension, including already visited entries; release once
at terminal operation completion. Nested unload/notification changes must
respect generation pins and the established notification-disable query.
Drain pending unload only after the notification sequence; its own callback can
block, so a synchronous drain at operation end is not a complete solution.
Treat that drain as a continuation sub-operation or explicitly stop scope before
claiming support for arbitrary nested loads/unloads.

Terminal cleanup policy must be explicit
Fault: retain the currently unfinished image's quarantine pin as current code
does, release other snapshot pins and gate once, report actual callback state,
and prevent retry/replay. Graceful ExitThread from attach: do not set
_dllAttachNotified or restore caller; transfer to exit handling once. Forced
TerminateThread: abandon operation without guest detach, release host-owned
gate once and quarantine unfinished image; never resume generator on dead
instance. Audit _markThreadExited, terminateThread, traps and teardown together.
An external stop must dispose or deliberately retain the operation; dropping a
JS object while its shared atomic gate remains owned deadlocks future callbacks.
