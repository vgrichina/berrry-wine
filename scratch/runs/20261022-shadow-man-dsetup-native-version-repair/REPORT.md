## Implementation

`lib/dll-registry.js` now allows **installed app-local DSETUP.DLL** through the shared native dependency graph. There is no bundled download path, ordinal alias, replacement handler or executable patch. DSETUP32/16 are not newly allowlisted: they are not static dependencies of this version-reader call. Existing DSETUP static imports and all other real-PE and child lookup paths remain unchanged.

`GetFileVersionInfoSizeA` and `GetFileVersionInfoA` now always use the existing named-file resource reader, as their W counterparts already did. A static DirectX basename no longer overrides a real file or returns canned metadata when no resource exists. The fabricated `$DX_VERSION_INFO` initializer was removed; its region and globals remain reserved, avoiding unrelated region moves and generated-map changes. Return values, DWORD handle writes, length-bounded copies and stdcall cleanup continue through the existing helpers/epilogues. No new last-error contract is invented: the unchanged named-file reader/host filesystem determines existing failure/error behavior.

The shared boot helper retains DirectX file-presence placeholders and `staticModule` loader exclusion, but gives them **no RT_VERSION**. This covers DDRAW, DSOUND, DPLAYX, D3DRM and D3D8 rather than leaving another invented DirectX fallback. Real installed entries are preserved. Previously retained placeholders explicitly marked `staticModule` are refreshed idempotently, so their old version resources cannot survive a normal mount. Unrelated OpenGL placeholder/version behavior is preserved, not qualified by this task.

`lib/storage.js` no longer seeds a fabricated DirectX `Version`/`InstalledVersion` registry key. Ordinary missing-key/value behavior therefore survives in fresh/reset state. Installer-supplied and imported registry values remain normal metadata, read verbatim with existing A/W encoding and buffer/error semantics. No runtime-support policy or minimum-version assertion was added.

**Persisted-state limit:** old registry snapshots have no provenance marker distinguishing a previous synthetic default from an installer writing the same string. This change does not delete existing values by guessing from their numeric content, or claim those values prove an installed/capable runtime. Likewise an imported file without the synthetic marker is treated as a supplied file, not classified by version number. The actual stopped installation's registry is unavailable here: its current branch, value and eventual native detector output remain unknown. Inspection of that exact preserved state belongs to coordinator qualification; no snapshot was queried or modified.
