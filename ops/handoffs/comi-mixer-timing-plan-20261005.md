## Evidence and new source finding

The October 3 immutable followup (`browser/followup/attempt2/` beneath `scratch/comi-audio-investigation-20261003`) measured 43 waveOut writes of 4096 bytes over 2.796 seconds, CALLBACK_NULL, producer thread 0, no auxiliary threads. Nineteen scheduled gaps totalled 859ms; the preceding header was observed DONE 31.48–46.975ms before each next write. Host write cost was at most 0.32ms. This is late main-thread refill, not the separate ScummVM CALLBACK_FUNCTION delivery defect. These are historical measurements, not requalified current-source results.

New bounded binary search finds the service's address is installed as a function pointer: COMI 424c6b writes 424ce0 into caller descriptor +18; 424c64 loads descriptor +1c and 424c7c stores that value into 48e7fc. The callback is therefore reached indirectly; no direct-call xref is expected. This does not identify its actual caller or prove timer cadence. Capture its owning entry stack return address next. `424cd0` merely reads 48e7fc. The later accumulator comparisons cannot be labelled a mixer throttle without recording the selected path.

Actual chain: 424ce0 tests reentrancy guard 46223c, calls 4224d0; that tests enable 46196c, calls wrapper 423430, then mixer 425030. Mixer reads 48ea0c startup/skip state, 48ea08 selects device-refill versus tick-accumulator path, calls refill at 425079 and 4251bb around real mixing (428ad0, voice loop 4264a0, output 4290a0). Refill 4230e0 tests 461c04, first header pointer, alternates 461c08, polls selected header WHDR_DONE at 42311e, then writes at 4231c9. Eight headers, not a single callback-driven buffer. Paired calls mean alternation alone is not evidence of half-rate output.

## Decision rules and safeguards

- Long ordinary page request gaps with little Worker execution: investigate host scheduling/presentation, with explicit sleep versus unaccounted gap distinction.
- Near-continuous Worker slices and infrequent service entry: investigate guest caller cadence / other guest work, not completion delivery.
- Frequent service entry but guard/DONE/toggle skips: identify exact live predicate and header generation; do not patch from aggregate rate.
- Mixer spending most diagnostic intervals internally: candidate mixing bottleneck only; confirm on uninstrumented profile before optimization.
- Successful mix/refill followed by late host write delivery: inspect existing RPC queue timestamps, separating Worker and page clocks using timeOrigin plus recorded calibration uncertainty.

Full helper deadline 180 seconds including launch and ordinary route; no automatic retries. Phase caps are immutable; cap or identity drift means incomplete, not absence. Preserve every actual served source/module/EXE hash and private Worker transformation separately. Recording hooks must fail closed on foreign hooks, preserve original return/throw/receiver, remove only own wrappers/timers and never override foreign replacements. Tests before launch: real-source anchor uniqueness; synchronous throw/rejected Promise/receiver forwarding; bounded records and cleanup; no destructive getters; partial pair and nested/reused-header rejection; canonical block-callback boundary proof only after CPU grant. Browser and server cleanup receipt required.

No runnable helper is claimed here: this is the reviewable bounded implementation plan. Current snapshots alone cannot determine whether a larger execution budget, faster mixing, or a guest pacing correction is appropriate. Increasing buffering would hide symptoms without establishing cause.
