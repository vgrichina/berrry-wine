# Recovery font startup comparison

Static review on 2026-11-06 against main `fd410ac25`. Recovery `6533ea42b` and `60dab3e4f` supply a bounded metadata catalog and executing-owner startup installation before guest DLL initialization. Current main lacks that interface; this does not by itself establish a current defect or justify a port.

Current browser startup in `host.js` awaits five required bitmap-font mounts and `loadSubstituteFonts()` before shared guest memory creation. The latter awaits the substitution manifest, subset font mounts, and optional matching code-page mounts. Substitutions are optional: fetch failure can produce missing faces. CLI `test/run.js` mounts resident bitmap and substitution bytes before guest execution and throws for missing bundled files. The shared path policy lives in `lib/font-substitutions.js`. These paths already order bundled font availability before execution, although they do not implement the recovery catalog transaction or its lifecycle seal.

The recovery design itself (`docs/design-font-preflight.md` at `60dab3e4f`) explicitly says demand-driven face preparation and generation-aware invalidation remain disabled, with later face reads synchronous. Its startup catalog therefore must not be described as fixing arbitrary lazy font reads. It also bounds catalog metadata separately from parsed faces and retained file generations.

Current `src/10c-truetype.wat` retains synchronous discovery: `tt_scan_font_dir` marks its one-shot scan flag before scratch allocation and directory registration. Callers include face lookup, substitution lookup, and wide-family lookup. `tt_enum_face_name` walks substitution and registered names; face metrics can enter discovery through `tt_face_for_logfont`. The early scan flag is a concrete boundary to examine if a font provider can suspend during discovery, but no current guest failure from that sequence was reproduced here. Allocation failure, absent directories, restart, and provider suspension must not be conflated.

Existing `test/test-wat-truetype-substitution.js` inserts resident bytes directly into the VFS before opening mapped styles, then checks parsed metrics and cache identity. This supports resident face resolution; it does not prove startup cancellation, asynchronous provider completion, or safe suspension inside drawing and callbacks. Likewise, source ordering is not a browser lifecycle test.

Disposition: keep this slice open, do not bulk-port it, and prioritize the reproduced host-import save journalling defect in `recovery-sparse-save-candidate-20261106.md`. Before assigning a font repair, reproduce a current user-visible failure with an executing-owner test covering initial publication, delayed or failed reads, stop/restart, and guest action exactly once. A later lazy-font implementation must prepare dependencies before output/stack mutation across text, metrics, enumeration callbacks, controls, Help, metafile playback, and direct exports; CreateFont-only preparation is insufficient. Preserve current TTC, subset, code-page, and bitmap replacement behavior.

No tests, build, module compilation, browser, or emulator run was performed for this comparison. No font production code changed.
