## Separate image-method implementation plan

Preserve the original proof bundle: `dx7-typelib.json`, `native-slot8.txt`, `ddsurfacedesc2-layout.json`, and `native-vb-desc-convert.txt` under the Jig scratch directory. Original DirectDraw7 IID `9f76fde7-8e92-11d1-8808-00c04fc2c602`, slot 8, is `CreateSurfaceFromFile(BSTR, DDSURFACEDESC2*, DirectDrawSurface7**)`, returning HRESULT. The original vtable target `73542a36` ends with `RET 16` at `73542cca`: four arguments including `this`, with total entry-to-return ESP advance 20. The observed generic stub advances 8 and returns `E_NOTIMPL`; neither defect is hidden by this dialog repair.

The VB descriptor is **232 bytes**, including a 128-byte pixel format at offset 72, caps at 200, texture stage at 216, linear size at 220, mipmap count at 224, and refresh rate at 228. Original conversion `7352be1a` maps it to native size 124 and invokes pixel-format conversion `7352a286`. Complete that pixel-format mapping and verify the actual output surface interface before implementation; the existing VB CreateSurface shim's direct native-descriptor call is not sufficient proof.

The proposed implementation must retain API ID 2542, assign its proven four arguments, and give only this slot a specific handler. Validate the BSTR and descriptor/output guest spans; load actual file bytes via the existing VFS/BMP decoder; allocate an actual owned surface; translate supported descriptor fields; copy decoded pixels with real pitch/orientation; return the correct VB wrapper and lifetime. Missing, invalid, unsupported, or allocation-failed inputs must return an honest HRESULT with safe cleanup. Do not return a dummy surface or constant success, or change other generic slots to success.

Required actual-WASM tests before acceptance: caller stack cleanup on success and failure, sparse-page descriptor/output spans, 232-byte descriptor canaries, asymmetric known BMP corner pixels and pitch, missing/invalid files, null pointers, allocation/decode failure cleanup, BSTR encoding, wrapper identity/refcount and destruction. Native error behavior should be checked before prescribing exact HRESULTs beyond proved cases. An ordinary valid-BMP puzzle run remains a separate qualification gate; later VB surface methods may still block it.
